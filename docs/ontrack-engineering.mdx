[`@trivoallan/ontrack-engineering`](https://www.npmjs.com/package/@trivoallan/ontrack-engineering)
is the reference track: 26 conventions on how a Python or TypeScript
repository on GitHub is engineered, each with the values it recommends.
ontrack is built with it, and rules on every one of its conventions in
[its own decisions](adr/engineering/ADR-0001-record-architecture-decisions.md).

## What you get

<CardGrid>
  <Card title="Agents" icon="laptop">
    The conventions you accepted, written into the instructions block of `AGENTS.md`, which Claude Code, opencode and Copilot CLI read on every session; plugins pinned; the agent opens the pull request and never approves one; a person merges it, or approves it so the agent can; if you choose, the agent acts under its own GitHub identity.

    <DomainLink name="Agents" />
  </Card>
  <Card title="Architecture" icon="puzzle">
    A hexagonal core by default, where the domain depends on no I/O; the architecture documented in arc42's twelve sections, with C4 diagrams generated from a LikeC4 model kept as code.

    <DomainLink name="Architecture" />
  </Card>
  <Card title="Code" icon="seti:typescript">
    Validation at every boundary (`zod` or `pydantic`), a test coverage target you set, and your code scanned by CodeQL, its alerts blocking from `high`.

    <DomainLink name="Code" />
  </Card>
  <Card title="Decisions and docs" icon="document">
    Decisions kept as ADRs, docs in one language under one root.

    <DomainLink name="Decisions & docs" />
  </Card>
  <Card title="Delivery" icon="rocket">
    A pipeline designed once, with a blocking gate and releases cut from tags, that zizmor audits; a licence others can reuse the code under.

    <DomainLink name="Delivery" />
  </Card>
  <Card title="Supply chain" icon="seti:lock">
    gitleaks before every commit, dependencies admitted by a person with install scripts ignored, a CycloneDX SBOM scanned by Grype, SLSA Build Level 2 provenance, and the tools outside npm pinned in one place.

    <DomainLink name="Supply chain" />
  </Card>
  <Card title="Workflow" icon="approve-check-circle">
    One convention for commits and branch names, refused at the gate instead of argued in review.

    <DomainLink name="Workflow" />
  </Card>
</CardGrid>

<Aside type="note">
A check confirms the wiring is there, not that it is right. Reject any
convention that does not fit your repository: a rejection is a full ruling.
</Aside>
